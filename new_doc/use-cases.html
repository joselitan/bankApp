Use Cases

UML Use Case Diagram showing all system actors, their capabilities, and include relationships between use cases.

UML Use Case Diagram

The system exposes two roles: a Guest User (unauthenticated) who can register and log in, and an Authenticated User who has full access to banking operations after obtaining a JWT token.

Figure 2 — UML Use Case Diagram (SecureCore Bank, Sprint 1)

Actors

ActorDescription
Guest User Any unauthenticated HTTP client. Can register a new account or attempt to log in. Has no access to protected endpoints.
Registered User An authenticated user who has obtained a valid JWT Bearer token via login. Can access all banking operations.

Use Case Catalog

Use CaseActorEndpointDescription
Register Account Guest User POST /api/auth/register Create a new user with validated email, full name, and a password meeting the strength policy. Automatically triggers Create Default Savings Account.
Create Default Savings Account System (include) — Created atomically during registration. Balance starts at $0.00. The account number is a random 16-char hex string.
Login Guest User POST /api/auth/login Verify email + password. Returns a JWT token (30-min expiry) on success. Locks the account for 10 minutes after 3 consecutive failures.
View Account & Balance Registered User GET /api/accounts/me Retrieve the authenticated user's account number, current balance, and last 10 transactions ordered by most recent first.
Deposit Funds Registered User POST /api/transactions/deposit Add money to the account. Amount must be between $1.00 and $10,000.00. Logged to the audit table.
Transfer Money Registered User POST /api/transactions/transfer Send money to another registered user by email. Enforces daily limit, prevents self-transfer and overdraft. Atomic DB commit. Automatically includes Validate Daily Transfer Limit.
Validate Daily Transfer Limit System (include) — Computed as the sum of all transfer_out transactions on the current UTC day for the sender's account. Must not exceed $5,000.00.
Logout Registered User POST /api/auth/logout Stateless — the server returns confirmation and the client discards the token. No server-side revocation in MVP.
