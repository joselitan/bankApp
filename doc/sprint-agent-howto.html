What this agent automates

  • Plans sprint candidates using two JQL streams: features + regression bugs
  • Creates a new sprint on your BAN board (board id 34)
  • Adds selected issues to the sprint (deduplicated + capped)
  • Closes an active sprint and rolls over to the next sprint (manual trigger)
Safety defaults: the workflow runs in dryRun=true mode by default. Always run Plan first, review the issue list, then re-run with dryRun=false.

How selection works (features + regression bugs)

The agent uses separate JQL queries so you can control what’s considered “suitable” work. The default workflow inputs are:

Features JQL

project = BAN AND labels = ready-for-sprint AND issuetype in (Story, Task) AND statusCategory != Done ORDER BY priority DESC, created ASC

Use ready-for-sprint to explicitly opt items into planning.

Regression Bugs JQL

project = BAN AND issuetype = Bug AND labels = regression AND statusCategory != Done ORDER BY priority DESC, created ASC

Regression bugs are included automatically if they have the regression label.

Important: Done items are excluded by statusCategory != Done. That means even if a Done issue still has ready-for-sprint, it won’t be selected again. As additional hygiene, we also remove ready-for-sprint when marking issues Done.

Manual run (GitHub Actions)

  1. Go to GitHub → Actions → Sprint Agent → Run workflow
  2. Pick an operation and fill inputs

Operation: plan (recommended first)

  • dryRun: true
  • Review the JSON output in the workflow logs (selected issues)

Operation: create

  • Set sprintName (e.g., Sprint 2)
  • Set dryRun: false
  • Agent creates the sprint and adds selected issues

Operation: close-and-rollover

  • Provide closeSprintId (must be an active sprint)
  • Provide nextSprintName (e.g., Sprint 3)
  • Set dryRun: false
  • Agent closes the active sprint, creates the next sprint, and fills it

API regression bugs: auto-create in Jira (separate agent)

Regression bugs should be created automatically from test failures. We implement this as a separate agent: tools/jira/regression_bug_agent.py.

It reads pytest JUnit XML output, builds a fingerprint, searches Jira for an existing bug with that fingerprint, and creates a new Bug if needed (de-duplication).

Auto-filed bugs are labeled regression and pytest-regression so you can filter them easily.

CI wiring: the repo includes two workflows:
  • API Regression (pytest) → runs scheduled or manually and uploads test-results/pytest-junit.xml
  • Regression Bug Agent → triggers automatically if the regression run fails and files Jira bugs
