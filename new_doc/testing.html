Testing

Test suite architecture, coverage per JIRA ticket, and instructions for running tests locally and in CI.

Test Approach

All tests are API-level integration tests using FastAPI's TestClient (backed by httpx). There are no unit tests in isolation — each test exercises a complete HTTP request-response cycle including routing, business logic, database writes, and response serialisation.

This approach validates the full application stack and matches how the API is actually used by consumers.

Test Isolation

Each test gets a fresh, independent SQLite database. The conftest.py fixture creates a temporary database file using Python's tempfile module, patches the application settings, and tears down the file after the test completes.

# tests/conftest.py (simplified)
@pytest.fixture()
def client(monkeypatch):
    with temp_db_url() as url:
        # Override DATABASE_URL with a temp file
        monkeypatch.setattr(config_module.settings, "DATABASE_URL", url)

        # Recreate engine and session factory for the temp DB
        engine = create_engine(url, connect_args={"check_same_thread": False})
        session_module.engine = engine
        session_module.SessionLocal = sessionmaker(bind=engine)

        app = create_app()
        with TestClient(app) as c:
            yield c   # DB tables created via lifespan on app startup
✅
Because each test uses an isolated database file, tests are fully independent and can run in any order. No truncate or manual cleanup is needed.

Running Tests

# Run all tests
pytest

# Run with verbose output
pytest -v

# Run a specific file
pytest tests/test_transfer.py -v

# Run with coverage report
pytest --cov=app --cov-report=term-missing

# Using the Makefile
make test
