Reference

API Reference

Complete documentation for all 8 endpoints, including request bodies, response shapes, and error codes.

ℹ️
Base URL: http://127.0.0.1:8000  |  Swagger UI: http://127.0.0.1:8000/docs
All routes are prefixed with /api.

Authentication

Protected endpoints require a Bearer token in the Authorization header.

Authorization: Bearer <access_token>

Tokens are obtained from POST /api/auth/login and expire after 30 minutes.

System

GET /health

Health check. Returns the running status of the API. No authentication required.

Response 200

{ "status": "ok" }
GET /api/ping

Connectivity check on the API router. No authentication required.

Response 200

{ "pong": true }

Auth

POST /api/auth/register

Create a new user account. A default Savings account (balance $0.00) is created atomically in the same database transaction. A register_success audit log entry is written.

Request Body

{
  "email":     "alice@example.com",   // Valid email address (unique)
  "full_name": "Alice Smith",         // 1–255 characters
  "password":  "Secure1!"             // min 8 chars, 1 digit, 1 special char
}

Password Policy

  • Minimum 8 characters
  • At least 1 digit (0–9)
  • At least 1 special character (non-alphanumeric)

Response 201 — Success

{
  "id":             1,
  "email":          "alice@example.com",
  "full_name":      "Alice Smith",
  "account_number": "a1b2c3d4e5f6g7h8"
}

Error Responses

StatusConditionDetail
400Password fails policy"Password must be at least 8 characters..."
409Email already registered"email already exists"
POST /api/auth/login

Authenticate with email and password. Returns a JWT Bearer token valid for 30 minutes. Tracks failed attempts and locks the account for 10 minutes after 3 consecutive failures.

Request Body

{
  "email":    "alice@example.com",
  "password": "Secure1!"
}

Response 200 — Success

{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type":   "bearer"
}

Error Responses

StatusConditionDetail
401Wrong email or password"Invalid credentials" (generic — does not reveal which is wrong)
423Account locked after 3 failures"Account locked"
🔒
After 3 consecutive wrong-password attempts, the account is locked for 10 minutes. The lock resets automatically — there is no manual unlock endpoint in the MVP.
POST /api/auth/logout

Stateless logout. The server does not maintain a token denylist in the MVP. The client must discard the token. Tokens expire automatically after 30 minutes.

Response 200

{ "logged_out": true }

Accounts

GET /api/accounts/me 🔐 Auth required

Returns the authenticated user's account balance and the last 10 transactions ordered by most recent first.

Response 200 — Success

{
  "account_number": "a1b2c3d4e5f6g7h8",
  "balance": "1500.00",
  "recent_transactions": [
    {
      "type":        "transfer_in",
      "amount":      "200.00",
      "created_at":  "2026-06-09T14:30:00Z",
      "description": "from=bob@example.com"
    },
    {
      "type":        "deposit",
      "amount":      "500.00",
      "created_at":  "2026-06-09T10:00:00Z",
      "description": null
    }
  ]
}

Transactions

POST /api/transactions/deposit 🔐 Auth required

Deposit money into the authenticated user's account. Amount must be between $1.00 and $10,000.00 per operation. Creates a deposit transaction record and a deposit audit log entry.

Request Body

{ "amount": "250.00" }

Response 201 — Success

{
  "deposited": "250.00",
  "balance":   "750.00"
}

Error Responses

StatusConditionDetail
401Missing or invalid token—
400Amount below minimum"Minimum deposit is 1.00"
400Amount above maximum"Maximum deposit is 10000.00"
POST /api/transactions/transfer 🔐 Auth required

Transfer money from the authenticated user to another registered user identified by email. The operation is fully atomic — both account balances update in a single database commit (BAN-16).

Request Body

{
  "to_email": "bob@example.com",
  "amount":   "150.00"
}

Business Rules Enforced

  • Minimum transfer amount: $0.01
  • Recipient must be a registered user (looked up by email)
  • Cannot transfer to yourself
  • Sender must have sufficient balance
  • Total outgoing transfers today must not exceed $5,000.00 (UTC day)

Response 201 — Success

{
  "transferred": "150.00",
  "to":          "bob@example.com"
}

Error Responses

StatusConditionDetail
401Missing or invalid token—
400Amount below $0.01"Minimum transfer is 0.01"
400Recipient email not found"Invalid recipient"
400Transferring to self"Cannot transfer to self"
400Not enough funds"Insufficient funds"
400Daily limit would be exceeded"Daily transfer limit exceeded"
ℹ️
All transfer failure cases are logged to audit_logs with the relevant details string before the 400 response is returned.

HTTP Status Code Summary

CodeMeaning

201Created — successful register, deposit, or transfer
400Bad Request — validation failure or business rule violation
401Unauthorized — missing/invalid token or wrong credentials
