GitHub Actions Setup

Run sprint planning + Jira automation from CI (safe, repeatable)

← Overview Sprint loop Prereqs Secrets Modes Status
Goal

Make Jira → Sprint planning automation reproducible via Actions

This page documents what you need to wire up GitHub Actions so an orchestrator workflow can read from Jira, generate sprint plans, and (optionally) update Jira statuses—without manual steps.

Start Plan-only Then Jira updates Eventually PR automation
Safety first
Recommendation: begin with a workflow that only generates a sprint plan artifact (no Jira writes).
When you’re confident, enable Jira writes (comments/transitions). Only later add auto-PR creation.

1) Prerequisites

GitHub

  • A GitHub repository containing this project
  • Actions enabled for the repository

Jira

  • Jira Cloud site (example): https://joselitan.atlassian.net
  • Project key: BAN
  • Atlassian API token created from your Atlassian account

2) GitHub Actions secrets to create

Add these in Repo Settings → Secrets and variables → Actions. Never commit tokens into the repo.

Required secrets

JIRA_BASE_URL = https://joselitan.atlassian.net JIRA_EMAIL = (your Atlassian email) JIRA_API_TOKEN = (create at id.atlassian.com/manage-profile/security/api-tokens)

Optional (nice to have)

JIRA_PROJECT_KEY = BAN
Tip: API token should have the minimum access needed (read-only for Mode 1).

3) Automation modes (choose your comfort level)

Mode 1 — Plan-only Recommended start

  • Reads Jira backlog via JQL
  • Generates SPRINT_PLAN.md and uploads as an artifact or opens a PR
  • No Jira writes

Mode 2 — Plan + update Jira

  • Adds comments to stories with plan/PR links
  • Transitions statuses (forward-only) based on PR/CI outcomes
  • Still no auto-merge to main

Mode 3 — Plan + implement (PR automation)

  • Agent creates branches/PRs per story
  • CI validates; humans review/merge (recommended at first)
  • Most powerful—and easiest to misuse without guardrails
Guardrail: PRs only. Never direct push to main.

4) Status (what’s done vs what’s next)

This is a lightweight checklist you can update as the project evolves.

Accomplished

  • Jira connectivity verified
  • BAN backlog created (epics + stories) with strong Acceptance Criteria
  • Documentation site created in doc/ (overview + sprint loop)
  • New epics created: BAN-28 (Frontend UI/UX), BAN-29 (QA/Automation)
  • GitHub Actions Jira secrets verified (Verify Jira Secrets workflow)
  • Mode 1 Sprint Orchestrator implemented (plan-only, no Jira writes) on branch option-a/sprint-orchestrator

Next up (recommended order)

  • Run Sprint Orchestrator (Mode 1 - plan only) on the option-a/sprint-orchestrator branch
  • Download and review the artifact sprint-plan (contains SPRINT_PLAN.md + issues.json)
  • Tune tools/jira/jql.txt (scope rules) until the plan matches your sprint selection process
  • Open a PR from option-a/sprint-orchestrator → main and merge when you’re happy
  • Later: enable Mode 2 (comments/status transitions)
  • Later: enable Mode 3 (auto-PR creation per story)
