Sprint 2 Scope & Goals

Sprint 2 extends the banking API with administrative controls, enhanced security, and QA artefacts:

  • RBAC (BAN-8): Customer vs Admin roles enforced at the API layer. All admin endpoints return HTTP 403 to customers. Default role for new users is Customer.
  • Security Headers (BAN-9): FastAPI middleware adds X-Content-Type-Options, X-Frame-Options, and Content-Security-Policy to every response.
  • Account Freezing (BAN-12): Admin-only POST /api/admin/accounts/{id}/freeze and /unfreeze. Frozen accounts are blocked from transfers. Logged to audit table.
  • Admin Dashboard (BAN-13): GET /api/admin/users returns all users with their total transaction counts. Admin-only.
  • External Withdraw + 2FA (BAN-17): Two-step flow — POST /withdraw/start generates a short-lived dummy code; POST /withdraw/confirm validates it and deducts balance atomically.
  • Test Plan (BAN-23): TEST_PLAN.md covering happy-path, boundary, negative/security, and UI/UX manual scenarios mapped to FR/NFR IDs.
  • Bug Report Template (BAN-24): BUG_REPORT_TEMPLATE.md with standard sections (summary, environment, severity, steps, expected vs actual, attachments).

Sprint Lifecycle in Jira

Sprints on board 34 are managed programmatically via tools/jira/agile.py. The full lifecycle from creation to activation is:

StepFunctionJira StateDescription
1 create_sprint(board_id, name) future Creates the sprint shell on the board. No dates set yet. Sprint appears in backlog.
2 add_issues_to_sprint(sprint_id, keys) future Moves tickets from the backlog into the sprint. Tickets become visible in the sprint column on the board.
3 start_sprint(sprint_id, start_date, end_date) active Activates the sprint. Sets start/end dates, transitions state to active. The sprint now appears on the active board view and is trackable.
4 close_sprint(sprint_id) closed Closes the sprint at the end of the iteration. Any unfinished tickets are moved to the backlog or next sprint automatically by Jira.
